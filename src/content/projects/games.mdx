## What it is

A single launcher fronting 22 finished, playable games across five categories: action, puzzle, racing, kids, and a couple of bigger originals. Shared infrastructure sits underneath: a common UI, an idle-guard that saves state and returns to the arcade after ten minutes of inactivity, and a zero-dependency Node server. Everything is vendored locally, no external CDNs.

It started as a rehearsal space. Game design answers "is this actually good to use" in seconds, which is the same question I ask on every product, just with a faster loop. Two of them grew big enough to earn their own entries:

- **Xenofall**, a real-time 3D first-person shooter built on Three.js with a fully synthesized soundtrack.
- **Global Gumshoe**, a procedural geography-detective game whose engine proves its own cases are solvable on every build.

## What's underneath

- **Shared launcher and idle-guard.** One UI mounts every game; the idle-guard saves progress and unmounts after inactivity so a device never gets stuck in a single game.
- **Lazy loading.** Only one game is in memory at a time; navigating back frees it.
- **Local-only assets.** No external CDNs at runtime. Three.js and everything else is vendored.

## What's real about it

The arcade is live and publicly playable, auto-deployed from source. The engineering underneath is the part I'd point at: shared infrastructure, local-only assets at runtime, and real test suites on the two big titles. Not a folder of one-offs.
