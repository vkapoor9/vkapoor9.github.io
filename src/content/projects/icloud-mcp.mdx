## Why I built this

An assistant that cannot see your inbox is guessing about your day. The existing options wanted either a cloud relay holding a copy of everything, or a token with full account access and no notion of what it was allowed to do with it. Neither is acceptable for a personal mailbox, so I wrote the server.

## How it works

- **33 tools** across mail (18), calendar (6) and contacts (3), plus triage and status utilities.
- **Read freely, send under a gate.** Sending is a per-account capability that can be switched off in config, so the restriction is structural rather than advisory.
- **Morning brief and de-noise.** Rules-driven triage plus automated unsubscribe, so the signal in a mailbox is reachable without reading all of it.
- **Two accounts, separately credentialed.** Credentials live in the macOS Keychain under per-account service names. Never in a dotfile, never in the repo.

## What it took

Zero third-party git code. I read two open-source servers for their ideas on security and triage and then wrote the implementation, because a supply-chain risk in the thing holding your mail credentials is not a tradeoff worth making.

The test suite is 285 cases, and the number that matters more is the verification baseline written into the project docs: expected folder count, contact count, calendar count per account. When a tool returns an empty list, the baseline is what distinguishes "nothing matched" from "the connection silently broke", which is a distinction no exception will make for you.

## What I learned

Building the integration was a week. Deciding what the assistant should be allowed to do, and then enforcing it somewhere a model cannot talk its way past, was the actual project.
